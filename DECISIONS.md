# DECISIONS

Architecture
- Vanilla JS static app in `app/`, no build step, served by `app/run.sh` (python http.server). Reason: one Chrome browser, one learner, zero infrastructure.
- All content is JSON under `app/content/courses/<course>/` (lessons, review-n, homework-n, course.json map) and `app/content/exams/`; `app/content/manifest.json` is generated by the validator. Reason: content agents never touch engine code.
- Python runs in Pyodide 0.27.7 from jsDelivr (NumPy, pandas, SciPy, scikit-learn 1.6.1, statsmodels, matplotlib, pytest); C++ runs in YoWASP clang 21 (libc++) in WebAssembly. Self-host fallback copies in `app/vendor/`. Reason: real runnable code without a server.
- The `arch` package is not in Pyodide: GARCH is fitted by hand (NumPy likelihood plus scipy.optimize). Rejected: adding a wheel (no network at runtime beyond jsDelivr).
- No network data: every dataset is generated in code with `np.random.default_rng(seed)`; project courses say what to change for real data (yfinance with caching, Nasdaq Data Link).
- Expression grading is numeric at six seeded points over free symbols; symbolic only when nothing evaluates. Rejected: symbolic-only (rejects e^{x+y} = e^x e^y). `\binom` and symbolic factorials are not gradable.
- Git and terminal courses teach by reading and tracing (no shell in the browser). Everything else runs real code.
- Progress data keys on lesson ids, so lessons are never renamed or removed; gap content is appended as new levels.

Content process
- Stage 0 gets topic exams topic-0.1 to topic-0.5 like every other stage (27 Oct); the original Stage 0 plan wrote only the stage exam, so the Learn screen's topic chips led nowhere.
- One level per agent from a brief in `docs/briefs/<course>.md`; the agent validates, plays through with screenshots, writes `docs/reports/<course>-<level>.md`, appends engine limits to `docs/BACKLOG-INBOX.md`, hands back six lines. Reason: orchestrator context stays small.
- Briefs are written by brief-writer agents from `course.json`, `curriculum.md` and `docs/briefs/EXAMPLE.md`; the orchestrator never writes per-lesson design.
- Content agents check a brief's own numbers before using them and record departures (27 Oct: multivar L5's 10% target under a 50% cap was infeasible, max 9.5%).
- Every stated number is computed twice (generator plus independent check, or CPython plus Pyodide). Every code solution passes its hidden tests and the starter fails them.
- Second reader per completed topic writes `docs/reviews/review-<topic>.md`; a fix agent applies targeted edits and appends `## Fix pass`. Coverage gaps become new levels, not edits to existing lessons.
- Voice rules (AUTHORING.md): British English, no exclamation marks, sentences under 20 words, explanations of at most three sentences, £ for money, `\operatorname{Var}`, `\text{£}` inside maths. Trees course: (1 + r) per step in l5 and the first screens of l7, e^{rΔt} from l6 onwards (stated).
- Maths breadth pass (27 Oct, user request): seven gaps against a traditional maths degree (proof, analysis and abstract linear algebra, ODEs and vector calculus with complex numbers, numerics and optimisation, statistical modelling, measure theory and PDEs, pure mathematics) become topics 0.6, 1.10, 1.11, 2.5, 2.6, 3.4 and additions to 3.2, plus a 1.5 gap level, in `docs/curriculum.md`. It runs before the rest of Stage 3. Counted hours rise from 3,100 to 3,530; 3.2 and 3.4 stay optional and uncounted. New topics rather than levels inside 1.3 to 1.6, because those exams sit at the 30-item cap.
- Breadth items are tagged [Quant] (needed for a quant career, with roles) or [Pure maths] (degree breadth, not needed to be hired) in `docs/curriculum.md`, and carry `strand` in `course.json` for an in-app badge (27 Oct, user request). Untagged courses are the core quant path. Pure maths: proof (0.6), 1.10, vector calculus, 3.4 (200 counted hours; quant path 3,330 h). Pure items never gate a stage on the quant path.
- Topic exams stay at 30 items or fewer (validator cap); when an extension needs more asks, pack them into multi-part table items rather than raise the cap (27 Oct, exam extension 1.3 to 1.5).
- Conventions fixed by fix passes: "hit rate" means P(right | call); P(flash | up) is the "detection rate". Per cent widgets store the fraction with `unit: "%"` (the engine divides typed input by 100). Singularity is checked by `matrix_rank` or `cond`, never a determinant threshold.
- Content agents ran on Opus through 26 Oct; from the migration, implementation agents run on Sonnet and the main session only plans and reviews (user instruction).

Engine process
- Backlog items are numbered in `docs/ENGINE-BACKLOG.md`; integration passes fix a range and write a status block. Content agents never edit engine files; engine passes never edit content.
- The code widget's time budget is 5 s per case for the whole run plus 30 s for heavy imports; slow solutions are caught with large inputs or a hidden counting subclass, not wall-clock asserts.
- Sandboxes without jsDelivr build the `--local-cdn` folder from GitHub releases and npm with `app/tools/fetch-local-cdn.sh` (27 Oct). Reason: plain playthrough cannot load Pyodide or clang there.
- Playthrough takes screenshots after `enter` patches settle; `--local-cdn` points at a scratchpad package folder in sandboxes where jsDelivr is blocked.

Rejected
- One agent per course (too long, lost to rate limits); one agent per level is the unit.
- Long hand-back reports (cost orchestrator context); replaced by files plus six lines.
- Removing duplicate lessons flagged by readers (breaks progress ids); duplicates stay, new levels add what is missing.
- Shuffled or random cross-validation anywhere in finance courses; time-ordered only.
