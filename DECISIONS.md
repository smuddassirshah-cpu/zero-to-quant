# DECISIONS

Architecture
- Vanilla JS static app in `app/`, no build step, served by `app/run.sh` (python http.server). Reason: one Chrome browser, one learner, zero infrastructure.
- All content is JSON under `app/content/courses/<course>/` (lessons, review-n, homework-n, course.json map) and `app/content/exams/`; `app/content/manifest.json` is generated by the validator. Reason: content agents never touch engine code.
- Python runs in Pyodide 0.27.7 from jsDelivr (NumPy, pandas, SciPy, scikit-learn 1.6.1, statsmodels, matplotlib, pytest); C++ runs in YoWASP clang 21 (libc++) in WebAssembly. Self-host fallback copies in `app/vendor/`. Reason: real runnable code without a server.
- The `arch` package is not in Pyodide: GARCH is fitted by hand (NumPy likelihood plus scipy.optimize). Rejected: adding a wheel (no network at runtime beyond jsDelivr).
- No network data: every dataset is generated in code with `np.random.default_rng(seed)`; project courses say what to change for real data (yfinance with caching, Nasdaq Data Link).
- Expression grading is numeric at six seeded points over free symbols; symbolic only when nothing evaluates. Rejected: symbolic-only (rejects e^{x+y} = e^x e^y). `\binom` and symbolic factorials are not gradable.
- Git and terminal courses teach by reading and tracing (no shell in the browser). Everything else runs real code.
- Progress data keys on lesson ids, so lessons are never renamed or removed; gap content is appended as new levels.

Content process
- Stage 0 gets topic exams topic-0.1 to topic-0.5 like every other stage (27 Oct); the original Stage 0 plan wrote only the stage exam, so the Learn screen's topic chips led nowhere.
- One level per agent from a brief in `docs/briefs/<course>.md`; the agent validates, plays through with screenshots, writes `docs/reports/<course>-<level>.md`, appends engine limits to `docs/BACKLOG-INBOX.md`, hands back six lines. Reason: orchestrator context stays small.
- Briefs are written by brief-writer agents from `course.json`, `curriculum.md` and `docs/briefs/EXAMPLE.md`; the orchestrator never writes per-lesson design.
- Content agents check a brief's own numbers before using them and record departures (27 Oct: multivar L5's 10% target under a 50% cap was infeasible, max 9.5%).
- Every stated number is computed twice (generator plus independent check, or CPython plus Pyodide). Every code solution passes its hidden tests and the starter fails them.
- Second reader per completed topic writes `docs/reviews/review-<topic>.md`; a fix agent applies targeted edits and appends `## Fix pass`. Coverage gaps become new levels, not edits to existing lessons.
- Voice rules (AUTHORING.md): British English, no exclamation marks, sentences under 20 words, explanations of at most three sentences, £ for money, `\operatorname{Var}`, `\text{£}` inside maths. Trees course: (1 + r) per step in l5 and the first screens of l7, e^{rΔt} from l6 onwards (stated).
- Maths breadth pass (27 Oct, user request): seven gaps against a traditional maths degree (proof, analysis and abstract linear algebra, ODEs and vector calculus with complex numbers, numerics and optimisation, statistical modelling, measure theory and PDEs, pure mathematics) become topics 0.6, 1.10, 1.11, 2.5, 2.6, 3.4 and additions to 3.2, plus a 1.5 gap level, in `docs/curriculum.md`. It runs before the rest of Stage 3. Counted hours rise from 3,100 to 3,530; 3.2 and 3.4 stay optional and uncounted. New topics rather than levels inside 1.3 to 1.6, because those exams sit at the 30-item cap.
- Breadth items are tagged [Quant] (needed for a quant career, with roles) or [Pure maths] (degree breadth, not needed to be hired) in `docs/curriculum.md`, and carry `strand` in `course.json` for an in-app badge (27 Oct, user request). Untagged courses are the core quant path. Pure maths: proof (0.6), 1.10, vector calculus, 3.4 (200 counted hours; quant path 3,330 h). Pure items never gate a stage on the quant path.
- Topic exams stay at 30 items or fewer (validator cap); when an extension needs more asks, pack them into multi-part table items rather than raise the cap (27 Oct, exam extension 1.3 to 1.5).
- Conventions fixed by fix passes: "hit rate" means P(right | call); P(flash | up) is the "detection rate". Per cent widgets store the fraction with `unit: "%"` (the engine divides typed input by 100). Singularity is checked by `matrix_rank` or `cond`, never a determinant threshold.
- Content agents ran on Opus through 26 Oct; from the migration, implementation agents run on Sonnet and the main session only plans and reviews (user instruction).
- Breadth plan (27 Oct): 13 courses, 49 levels, 218 lessons; markov L5 covers martingales and optional stopping only, because the Poisson process is already markov l16; stage hours and exit lines in curriculum.json are left for the engine item.
- Breadth briefs (27 Oct): pure courses never grade a free-form proof; each proof step is graded by `order`, `choice`/`multi` or a fill-in widget, and whole proofs go to `longform` homework with a 10-point rubric. Complex answers are graded as Re and Im (or modulus and argument) parts, never as a complex `expression`. Brief-writers ran on Opus (user instruction for this item). The Re-and-Im split is superseded (brief revision, 28 Oct): `expression` grades a complex value by real and imaginary parts at every seeded point, and a vector entry by entry, so the briefs now ask for one complex or vector `expression`; separate parts stay only where a part is the point (a modulus, an argument). Code screens compare complex results with `isclose` (Python `cmath`, C++ `expect: { "re", "im" }`).

- Breadth briefs 2 (28 Oct): where a brief-writer prompt and `course.json` disagreed, the map won (numerics L4 prices by finite differences, quadrature and Monte Carlo with a control variate, the tree kept as a fourth check; pdes cites odes l2, l6, l7, l10, l16 to l18, numerics cites odes l16 to l18). Brief-writers ran on the main session's model, as in the first breadth briefs.

Engine process
- Tested out (28 Oct, user request, item 449): a passed topic exam makes Today, Learn's up-next and the course map skip that topic's courses unless a lesson is open to resume. It is derived from saved exam attempts at read time, so no lesson flag is stored, no migration runs and progress figures stay honest. Rejected: marking the lessons done (inflates progress). Exam misses stay in the redo queue.
- Backlog items are numbered in `docs/ENGINE-BACKLOG.md`; integration passes fix a range and write a status block. Content agents never edit engine files; engine passes never edit content.
- The code widget's time budget is 5 s per case for the whole run plus 30 s for heavy imports; slow solutions are caught with large inputs or a hidden counting subclass, not wall-clock asserts.
- Sandboxes without jsDelivr build the `--local-cdn` folder from GitHub releases and npm with `app/tools/fetch-local-cdn.sh` (27 Oct). Reason: plain playthrough cannot load Pyodide or clang there.
- Playthrough takes screenshots after `enter` patches settle; `--local-cdn` points at a scratchpad package folder in sandboxes where jsDelivr is blocked.
- Strand badges (27 Oct): violet "Pure maths", amber "Quant", detail from `strandNote`; a topic or exam chip shows a badge only when all its courses share a strand. "Quant path only" hides pure courses and all-pure topics and drops them from stage gating and progress. Learn shows every topic's `exit` as a Target line.

Rejected
- One agent per course (too long, lost to rate limits); one agent per level is the unit.
- Long hand-back reports (cost orchestrator context); replaced by files plus six lines.
- Removing duplicate lessons flagged by readers (breaks progress ids); duplicates stay, new levels add what is missing.
- Shuffled or random cross-validation anywhere in finance courses; time-ordered only.
- Breadth engine item (27 Oct): five parallel engine agents each owned disjoint files and wrote shared-file changes into their reports; one integration agent applied them. 3D is its own SVG canvas `space` (painter's order, no WebGL), capped at about 1,600 surface cells for smooth mobile drag; complex maps are a separate `complex-map` canvas rather than a `plane` mode. A bare `i` in an expression answer is the imaginary unit.
- Interview readiness first (29 Oct, user priority): the app must be a complete, self-contained resource for passing quant internship OAs and superdays (Two Sigma, JP Morgan, trading firms, bank strats). PLAN task 2a (gap research, interview plan, topic 3.3 and ito, mock OAs and superdays, interview-critical fix passes) runs before the remaining breadth levels; Pure maths levels wait. Reason: Stage 3.3 and Ito are what interviews test, and the Pure strand helps none of them.
- Reports for the `analysis` course are returned as text and saved by the main session (29 Oct, user decision), because Claude Code's Write tool refuses subagent writes to `.md` files named `analysis*`.
- Interview plan decisions (29 Oct, user): target summer 2027 opportunistically and 2028 fully; recruiting content leads with the UK and Europe cycle; trader and researcher tracks first, developer and strats depth last; no microphone recording (engine item E10 dropped). Main session: new topics 0.7 (Getting hired) and 3.5 (Interviews by role); mock OAs and superdays are their own exam kind (`exams/mock-*.json`).
- Firm names (2 Nov): only recruiting l4 and mock exam descriptions name firms; elsewhere a firm's public resource is cited by title and firm type (puzzles l7: "Probability and Markets, a free guide from a trading firm"), even where a brief names the firm.
- Prep tags (2 Nov, user request): lessons are tagged for assessments through one central file, `content/prep.json` (paths: general, OA, interview and superday by track, one per firm), not fields on lessons. Firm names are allowed there, marked as reported with an `asOf`. Each lesson shows at most one chip. Reason: firm facts go stale each cycle, lesson ids are fixed, and paths can name unwritten levels.
- Section by section (2 Nov, user decision): finish one topic at a time (every level, its topic exam, second read and fix, green playthrough) before starting the next; within a topic finish one course before the next; write each mock as soon as its content is complete. Order in PLAN 2a: prep tags, topic 0.7, 3.3, 3.5, 3.2, appended levels, then 2b. Reason: each finished section can be studied and consolidated at once instead of waiting for scattered later levels.
- [Superseded 2 Nov by "Standards restored" order] Gaps first (2 Nov, user decision, applies from the next session): complete every course already started and write every topic exam its topic allows (PLAN 2a Part G) before starting any course with no lessons (Part N). Started Pure courses (analysis L5, linear-maps L4) are included, reversing the Pure-waits rule for them. Reason: existing sections become studyable end to end sooner.
- [Withdrawn 2 Nov: see "Standards restored"] Superday sprint (2 Nov, user decision: "a learnable app as soon as possible, polish later"): PLAN 2a Part S runs first, replacing gaps-first and section-by-section as the immediate order. Interview-critical levels and mocks first (trader, then researcher), three or four content agents in parallel on different courses per session, second reads and non-blocking engine work deferred to Part P, content agents write missing level briefs themselves, lean acceptance. Correctness checks (numbers twice, code tests) are kept. Gaps (Part G) and new courses (Part N) follow.
- No target firm yet (2 Nov, user): readiness runs from foundations to superday topics, firm-neutral. Prep paths are ordered foundations first; firm paths are written last. The app stays on the laptop's local server (`app/run.sh`); no hosting.
- Standards restored (2 Nov, user decision, supersedes the superday sprint entry): no quality cuts for speed. Every level keeps full LEVEL-BRIEF acceptance and a written brief made before it; every topic closes with its exam, mocks, a second read and fix pass; engine features a course needs (E7 bank spacing, E9 per-item timing, E12 trading-game widget) are built before its levels, so mm-games L3 and L4 use the widget, not scripts. Kept from the sprint: interview-first order, firm-neutral paths, parallel agents across courses, and an answer-check agent each session (additive). Rejected: the lean sprint rules (no second reads, self-written briefs, scripted games, deferred bank and timing, deferred topic exams, short acceptance).
- Firm names in recruiting level 1 (2 Nov, fix pass 0.7): l1, l2, l3, l5, review-1 and homework-1 now use firm types, letters or invented firms; firm-specific facts point to l4. This applies the 2 Nov firm-names rule to files written the same day.
- Session branch (2 Nov): the harness assigned `claude/recruiting-l3-game-theory-nvxp1s`; work was rebased on `claude/amazing-wright-d4mx7i` before each push and pushed to the assigned branch, so it fast-forwards onto amazing-wright. Merge it there before the next session starts.
- Voice check (3 Nov): `docs/reviews/voice-scan.py` (set `VOICE_BASE` to a course folder) is the shared check for the 20-word sentence and three-sentence explanation rules; a formula, code span or {{template}} value counts as one word. Every second read runs it, and a topic is not closed until it reports 0 and 0. Reason: topic 2.1 carried about 580 long sentences that earlier authoring missed.
- Mocks brief (4 Nov, `docs/briefs/mocks.md`): the engine's arithmetic generator (E4) makes whole-number items only, so mock-oa-arith is 64 generated items plus 16 fixed decimal, fraction and percentage items, with no separate versions. Until E3 draws fresh items, mock-oa-sig and mock-oa-trader ship three fixed versions as separate files (`-2`, `-3`), and `prep.json` names version 1 only. With no calculator panel (E15), the sig description says to bring a calculator, and arith and trader end with a self-ticked "no calculator" check. Reported SIG formats give no negative marking, so sig scores +1, 0, 0 and passes at 11 of 17. Trader paper C grades intervals as a four-option choice with one tightest interval holding the value.
- Distractors (4 Nov, mock-oa-arith): no item may put the key between a times-ten pair or between two equal slips, because the option pattern then gives the key away; the generator rejects such items.
- Parallel sessions (3 Nov, user request): session B ran topic 3.3 part two beside session A on the same branch, kept off engine files and mm-games, and rebased before every push. Works when each session owns disjoint files; the closing session writes the one NEXT_PROMPT.
- Trading games (3 Nov, engine pass D): mm-games L3 and L4 use the `trade` widget, whose authored `strategy` must reach the benchmark when the validator replays it; a learner's P&L passes to later screens by `carry` in lessons and sets only, so review and homework items use fixed numbers from the model run.
- Exam coverage (3 Nov): exam items link to levels only through `skills`; the stage status report counts a level covered when an item tests a skill first met in that level, and flags levels whose skills are shared with earlier levels.
- Numeric distractors (5 Nov, answer-check fix pass): the times-ten and equal-slip rule ("Distractors (4 Nov)") applies to options a learner sees; a numeric item's `wrong` values only route feedback, so they may sit either side of the key. Interval choices in the trader mocks carry `shuffle: true` like every other choice.
- Bank layout (6 Nov, `docs/briefs/bank.md`): bank part 1 is 20 files `bank/<family group>-<session>.json`; the engine reads an item's family from its first tag, and bank families reuse course tag names so the deck mixes them (`coupon-collector` became `every-coupon` and `derangements` became `hats` after the puzzles fix pass tagged level 1 by lesson slug). Behavioural items are typed `longform` with a six-line rubric (2, 2, 2, 2, 1, 1 points), spoken aloud first; `requires` only on difficulty 4 and 5 items.
- mock-superday-trader (6 Nov): one version only (the three-version rule covers the OAs, which learners resit), four papers scored with `pass` shares since nothing is marked negatively, three `trade` games graded right or wrong, five typed longform answers.
- Duplicates (6 Nov, answer check): a mock or bank item may not reuse the numbers of any course, exam or bank item; the answer checker greps all three folders, and the newer item takes fresh numbers.
- Tested-out resume (4 Nov, user bug report, ENGINE-BACKLOG 461): a lesson left open in a topic whose exam is passed no longer sets Today, Learn or the course page's current course; it does if the learner reopened it after the pass. Lesson progress is untouched.
- Bank second read (4 Nov): the brief's section 9 whole-bank read runs before the bank's PLAN tick even when an orchestrator prompt omits it, as full standards require. Choice keys may not be visibly longer than their distractors (14 items rebalanced).
- Topic 3.5 briefs (4 Nov): a brief may not carry a workaround or fallback for any engine gap, E-numbered or not. Every gap is either redesigned away with existing features (nine were) or raised as a labelled [Must] requirement (`C-parts-code`, `C-parts-mixed`, `C-parts-credit`, `C-data-cap`, `C-draw-code`, `C-drill-patterns`, `C-alloc-check`, `E13-blocked-lanes`) built in engine pass C before the level. Pass C runs in two parts: E11 and E14 first, then E8, E3, C-alloc-check and E13. Check scripts are kept in `docs/briefs/<course>-scripts/`, not only in the scratchpad.
- Branches (4 Nov): `claude/amazing-wright-d4mx7i` is the only live branch. A session started on a harness-assigned `claude/<slug>` branch checks out amazing-wright when it holds the same commit and pushes only there. `claude/plan-2a-topic-3-3-part-4-za61kk` and `claude/recruiting-l3-game-theory-nvxp1s` are stale copies with nothing unique. `main` and the `stage*` branches hold an earlier, separate TypeScript project.
- Engine pass C in parallel worktrees (4 Nov): four engine agents and the content authors each ran in their own git worktree and committed there; the main session merged each branch, resolved conflicts by hand and re-validated. A conflict left in a file outside the first conflict list (`drill.js`) broke every drill until a smoke run caught it, and a hand merge dropped one of three places that match drill packs (caught by the second read): after a hand merge, grep every file for conflict markers and re-run the affected playthrough before pushing.
- Engine samples (4 Nov, item 467): a file with a top-level `"sample": true` is listed under `samples` in the manifest and appears in no learner-facing list, count, deck or draw (except a sample exam drawing sample files). A sample lesson lives in an existing course folder unreferenced by `course.json`; a canvas sample may be a hidden mock.
- Fresh numbers in reviews and homework (4 Nov, answer checks): a review or homework item may not repeat the numbers and answers of a lesson in its own course, because it then tests recall of the answer, not the skill. This overrules a fix pass that called in-course reuse allowed; 8 items in coding-int L1, L2 and systems L1 and 10 in systems L2 were given fresh numbers.
- Canvas limits in lesson claims (4 Nov, systems L2): where the `interleave` canvas simplifies (wait, notify, no store buffer), a lesson states only what the canvas shows and teaches the real behaviour from a listing; a count such as "of 168" is stated only after the canvas reproduces it.
