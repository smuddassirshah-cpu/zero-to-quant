# Spike S1 probe: the contract every module follows

Build stage 2 of Zero to Quant (`docs/PLAN.md` section 11.3, row 2). The probe is a page published as a private claude.ai Artifact and run by the owner on his iPhone (iOS 18.7, Claude app). Its results decide architecture: a false pass is the worst defect a check can have. Every check must measure the property directly, record the raw evidence in `data`, and fail or say "inconclusive" rather than guess.

## Hard constraints (the Artifact publishing rule and the host)

- Every published file is our own code or data, written in this folder or generated by `tools/build.mjs`. Never copy third-party code into a published file. Third-party modules load at run time from `https://cdn.jsdelivr.net/npm/...` or `https://cdnjs.cloudflare.com/...` at exact versions, through the page's import map, or by full URL in a worker.
- Published file types: `.html .js .mjs .css .json .svg` only. No binaries, no fonts, no images other than SVG.
- The page is a fragment: the host wraps it in its own `<!doctype html><html><head>...<body>`. No `<html>`, `<head>` or `<body>` tags. `<title>Spike S1 Probe</title>` and the stylesheet link come first.
- The host's CSP: scripts only from our own files and the CDN hosts; stylesheets only from our own files and Google Fonts; `fetch` only to our own files (never a CDN, never another host); workers from our own files or `blob:`. No `alert`, `confirm`, `prompt`, `window.print`, iframes, `<object>` or `<embed>`. Links to `https://` open in a new tab. Only a plain `#anchor` from the artifact link reaches `location.hash`.
- Browser storage may throw: wrap every `localStorage` and `sessionStorage` access in `try`/`catch`.
- Capabilities come only through `window.claude.use(name)`, which resolves the namespace or `null` (and `null` after 10 s with no viewer). Never read `window.claude.db` or similar members. The type definitions are the `artifact-capabilities` skill's for runtime contract 0.2.73 (`claude.d.ts`, `db.d.ts`, `sample.d.ts`, `user.d.ts`, `permissions.d.ts`). Read the ones your module calls before writing code.
- No empty `catch`: every caught error is recorded in the result or logged.

## Writing rules for every string, comment and message

British English (colour, behaviour, recognise), no em dashes and no spaced en dashes (use commas, colons or full stops), no filler words (robust, seamless, leverage, pivotal, streamlined, cutting-edge, simply, obviously, clearly). Plain, specific, short. The owner reads these on a phone.

`harness.js` loads the four check modules with `import('./cdn.js')`, `import('./mathml.js')`, `import('./platform.js')` and `import('./caps.js')` (relative paths, no bare specifiers), so a failed import map cannot stop the harness.

## The module shape

Each check module is an ES module whose default export is:

```js
export default {
  id: 'cdn',                       // module id: cdn | mathml | platform | caps
  title: 'CDN modules and the import map',
  checks: [
    {
      id: 'cdn.importmap-bootstrap', // `<module>.<name>`, stable: results are keyed by it
      title: 'Import map honoured by the bootstrap',
      kind: 'auto',                // auto | manual | consent | republish | tool
      what: 'One sentence: what property this measures and how.',
      timeoutMs: 45_000,           // optional, auto, tool and republish only: replaces the kind's limit (at most 300 s)
      async run(ctx) { return { status: 'pass', summary: '...', data: { ... } } },
    },
  ],
};
```

A module may also export `resume(ctx)` on the default object: the harness calls it once at start-up, before any check runs, and it resolves `{ [checkId]: result }` for checks that finish across a page reload (the reload check stores a pending marker with `ctx.session.set`, calls `location.reload()`, and `resume` reports what loaded). `resume` resolves `{}` when nothing is pending.

- `auto`: runs on load, in order, one at a time, with a 30 s timeout each (or the check's own `timeoutMs`).
- `manual`: needs the owner (a tap, a gesture, a judgement); runs when he taps Run, and uses `ctx.ask`.
- `consent`: calls a capability that may ask for consent (`sample`); runs only on a tap.
- `republish`: waits on `ctx.republished` (Claude republishes the Artifact while the page stays open), then runs, with a 120 s timeout (or its own `timeoutMs`).
- `tool`: measured by Claude with the publishing tool, not on the device; `run` returns `{status: 'info', summary: 'Claude records this from the publishing tool'}`.

A result is `{ status, summary, data? }`:

- `status`: `pass` (the property holds), `fail` (it does not), `info` (a measurement with no pass bar: sizes, timings, versions), `inconclusive` (the check ran but cannot tell), `error` (the check itself broke; put the error in `data.error`), `skipped` (a precondition is missing; say which in `summary`).
- `summary`: one plain sentence, for example "The bootstrap's import('preact') resolved through the map in 412 ms."
- `data`: small, JSON-safe raw evidence (at most about 8 KB per check): the values measured, not conclusions.

## The context `ctx` the harness passes to `run`

```js
ctx.mount        // HTMLElement: this check's own output area (specimen sheets, sliders, links)
ctx.ask(prompt, choices)   // Promise<string>: shows the prompt and one button per choice; resolves the label tapped
ctx.note(prompt)           // Promise<string>: shows a text field and a Save button; resolves the text
ctx.log(line)              // appends one line to the check's log
ctx.claude(name)           // Promise<namespace|null>: window.claude.use(name), null if absent or after 10 s
ctx.version                // 'v1' or 'v2': the page version that is running (from #app's data-version)
ctx.lock                   // the parsed lock.json the build publishes (URLs, integrity, cdnjs candidates, bad-integrity entry)
ctx.republished            // Promise<{at, to, source, arrivedAt, arrivedPerf}>: resolves when a fresh ops/s1-republished says {to: 'v2'} ('db'),
                           // or when the owner starts the republish checks by hand ('manual'); arrivedPerf is performance.now() at arrival
ctx.session.get(key) / ctx.session.set(key, value)   // sessionStorage, JSON values, never throws
ctx.boot                   // window.__s1boot: what the fragment's classic bootstrap recorded before the harness loaded
ctx.now()                  // performance.now()
```

`lock.json` (generated, published) holds:

```js
{
  modules: [{ specifier, url, integrity, files, bytes, entryBytes }], // per import-map entry: the entry file's URL, integrity and size, the closure's file count and raw bytes
  umd: [{ name, global, url, integrity, bytes }],           // Preact 10.29.8 UMD, its hooks, signals-core and signals UMD
  cdnjs: [{ specifier, url, integrity }],                   // cdnjs candidate URLs for the same files, with the npm file's integrity
  badIntegrity: { url, integrity, bytes, second: { url, integrity } }, // a real CDN file listed with a deliberately wrong hash, its size, and a second wrong-hash URL (?s1-bad2)
  control: { url },                                         // the same file at a URL with a query string and no integrity entry
  workerImports: [{ name, url }],                           // classic zod, ts-fsrs and fflate entry URLs for the module worker
  capabilities: { ... },                                    // the declaration the page is meant to be published with (the runbook below)
}
```

## Result storage (the harness)

The harness writes one db document per run, `ops/s1-run-<runId>`, with `{ version, ua, viewport, startedAt, appVersion, deviceModel, results: { [checkId]: { status, summary, data, at, ms } } }`, serialised (one write at a time, at most one write per second), and `ops/s1-latest` `{ runId, version, at }`. If `db` is `null`, results stay on screen and the Copy results button exports the same JSON. Claude reads these documents with its ArtifactData tool.

## The publishing runbook (Claude, with the Artifact tool)

Every step names what it records. `dist/manifest.json` holds the SHA-256 of every file and `publishPlan`, the sizes below. The files were written by builder sessions and by `tools/build.mjs`, so the publishing session reads every file in full before its first publish (the Artifact tool requires it), loads the `artifact-capabilities` skill and checks the declaration against it.

1. **Build.** `node tools/build.mjs --strict` and `node tools/test.mjs` must both pass. Compare `dist/manifest.json` with the files read.
2. **v1.** Publish `file_path: dist/v1/index.html` with `files` mapping every other path of `dist/v1` to its source (`publishPlan.v1.files`, 215 entries), an `icon`, and `capabilities` exactly as `publishPlan.v1.capabilities` (ARCHITECTURE.md 6.2.4's rule set plus the canary `{ path: 's1canary/{self}', write: 'interact' }`; without the canary, caps.db-rules can only say inconclusive). Keep the URL: every later publish passes it.
3. **dbsize.** A separate Artifact: `file_path: dist/dbsize/index.html`, `files: { 'dbsize.js': 'dist/dbsize/dbsize.js' }`, `capabilities: { db: {} }`.
4. **Run v1.** The owner opens v1 on the iPhone, fills in the app version and the iPhone model, and waits for "S1 ready for republish".
5. **v2, the republish.** Publish with `url` set to the v1 URL (a different `file_path` without `url` creates a new Artifact and voids every republish check), `file_path: dist/v2/index.html`, and `files` as an object map: `version.json` and the 101 added paths to their `dist/v2` sources, and the 201 removed paths to `null` (the array form cannot carry `null`). Omit `capabilities` so v1's declaration is kept. Record the tool's answer, accepted or refused with its message, as `platform.null-removals`.
   - If the publish is refused for its size (`publishPlan.v2.entries`, 304 with the page), send `publishPlan.v2FallbackBatches[0]` and then `[1]`, each with `url`; record that `null` removals count against the 255. Send the signal only after both.
   - After the publish, list the files (`scope: files`): expect the 116 paths of `manifest.folders.v2`, with neither `data/v1-only.json` nor `bulk/b-001.json`.
   - v2 changes `index.html` (its `data-version`), so this publish cannot test omitting the page; step 8 does.
6. **The signal**, with ArtifactData as the owner, in this order, each `at` the current time in ISO 8601: set `meta/release` to `{ release: 's1-v2', at }`, then `ops/s1-republished` to `{ to: 'v2', at }`. The page takes a signal only when it differs from what was there when the page loaded, so always write a new `at`.
7. **After the republish checks.** The owner says "S1 republish checks done", then runs `platform.reload` on the same page, then `platform.back-gesture` and the other manual checks if not done yet.
8. **v3, omitting the page** (`platform.publish-omit-page`). Publish with `url`, no `file_path`, and `files: { 'data/v3-only.json': 'dist/v3/data/v3-only.json' }`. Record accepted or refused with its message. If accepted, read the page back: it must equal `dist/v2/index.html`; list the files: 117 paths, the v2 set plus `data/v3-only.json`.
9. **Results.** Read `ops/s1-latest`, then each `ops/s1-run-<runId>` (the v1 run and the run after the reload), and `status/s1-size` from the dbsize Artifact. The dbsize probe deletes its documents by itself after `done` or `capped`; the owner then confirms deleting the dbsize Artifact.
