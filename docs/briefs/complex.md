- **Complex answers are one `expression`.** An `i` (or `\mathrm{i}`) in the answer or the learner's input is the imaginary unit, and the grader compares the real and the imaginary part at every seeded point, so `\frac{1}{1+i}`, `\frac{1-i}{2}` and `0.5-0.5i` agree, `3-4i` fails for `3+4i`, and `0` fails for `(1+i)^2` and for `-2i`. `\overline{...}` and `\bar{...}` are the conjugate, and `e^{i\theta}` equals `\cos\theta + i\sin\theta`. Free symbols stay real: write `x + iy`, not `z`. A bare `i` is always the imaginary unit (ENGINE-BACKLOG item 446), so never use `i` as an index or variable in an `expression` answer; use `k`, `j` or `n`. A vector answer such as `(a, b, c)` or a `pmatrix` is also one `expression`. Do not split a complex answer into a Re cell and an Im cell, or into two `numeric` boxes, unless the screen asks for the modulus or the argument specifically.
- **`isclose` compares complex results.** A function may return a `complex`, a NumPy complex scalar or array, or a list of them, and `expect` is a Python expression such as `0.5-0.5j` or `[1+1j, 2-2j]`; the test is `cmath.isclose` with the case's `tol` (default relative 1e-9, absolute 1e-12), and a real `expect` against a complex result compares as a complex number. Return and test complex values directly: no `[w.real, w.imag]` splitting. (C++ would use `expect: { "re": 5, "im": 5 }`; this course is Python only.) Item 447: `drill.js` keeps a float-only `isclose`, so do not put a complex-valued function in a drill.
- The `numeric` widget takes one real number, so a complex answer is never one `numeric` box: use one `expression`.
- Canvas `derive` expressions on a `plane` have no complex arithmetic: write products out in real and imaginary parts (`p1.x*p1.x - p1.y*p1.y`), and use `hypot` and `atan2` for modulus and argument. On a `complex-map` the formula `f` does the complex arithmetic and each point carries `p1.u` and `p1.v`, the real and imaginary parts of f at `p1`, so captions need no hand-written products.
