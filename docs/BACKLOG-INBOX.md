# Engine backlog inbox

Content agents append their engine and canvas limitations here, under `Raised later (<course> level <n>):`, as bullets. An integration pass numbers them into `ENGINE-BACKLOG.md` and clears this file.


Raised later (cpp-pricing level 1):

- C++ runtime (libc++): a range-for over a braced list (`for (double x : {1.0, 2.0})`) fails to compile unless `<initializer_list>` is included directly or by another header; worth a line in AUTHORING section 3's C++ addendum.
- code widget (C++ and Python): `isclose` accepts any two numbers within 1e-12 of each other, so tiny values such as Φ(−10) = 7.6e-24 or 1 − cos(1e-8) cannot be tested directly. A per-case `rel` or `abs` tolerance on code tests is needed; authors currently write `f(x) / exact - 1` with expect 0, or scale the value up.
- `grade.js` `fmtNum`: rounds the test hook's and Show solution's numeric answer to 6 decimal places, so an answer like 9.5e-7 is filled in as 0.000001 and fails its own tolerance. Format with significant figures instead.
- plane canvas derive: a single `area` object cannot be targeted by its id (`A.to`); only `area.to` works. Either support it or document it in README-B.
- bars `sim`: it draws from the app's JavaScript generator, so a histogram cannot show C++ (libc++) draws live. Allowing `data` per control stop, or a seeded C++ source, would avoid precomputed derive tables.

Raised later (stat-learning level 2):

- plane canvas: the x-axis is always drawn at y = 0 when the y range spans 0, with its tick labels inside the plot, so signed coefficient paths (ridge and lasso paths against λ) run over the ticks. An `xAxis: "bottom"` option, the twin of `yAxis: "left"`, is needed; stat-learning l7 and l8 plot |β̂_j| instead.
- validator vs README-B: plane `functions` entries of the documented contour family (`{ "contour": "...", "levels": [...] }`, integration pass 5) are rejected ("a function needs expr, or x and y, or implicit"). stat-learning l8 draws each error ellipse as its own `implicit` curve. Either the validator should accept `contour`, or README-B should drop it.
- series canvas: the x axis is the array index only, so a curve against a non-integer or log-spaced grid (test MSE against λ = 0.01, 0.1, 1, 10, ...) cannot carry its real x values. Needed: numeric x values per series (or `xValues`), with `xScale: "log"` honouring them.
- derive: there is `matmul` but no linear solve or inverse, so ridge coefficients for correlated features cannot follow a λ slider live. stat-learning l7 and l8 use a design with uncorrelated features so the paths are closed-form; a `solve(A, b)` (small matrices) would allow real data.
- pair of bars side by side shrinks both charts until category labels and values are unreadable at the 540px column; stat-learning l9 sets `stack: true`. The pair could stack bars automatically below a minimum scale, as it already does for matrices.

Raised later (cpp level 2):

- C++ runtime (WebAssembly): undefined behaviour does not trap, so no lesson can show a memory bug failing in the browser. Probed: `*nullptr` read returns whatever is at address 0 (printed 1 and 0) and a null write succeeds; a pointer or reference to a dead local reads the stale value (101.25), or a later frame's value (7) once another call reuses the slot; use-after-free reads stale bytes; double `delete`, `delete[]`/`delete` mismatch and `delete` of a stack object all run silently with exit status 0; a reference into a vector after a reallocating `push_back` read 2.93699e-306. Only clang's compile-time warnings (`-Wreturn-stack-address`, `-Wmismatched-new-delete`) appear. Lessons teach these through `console` canvases of real g++ `-fsanitize=address` output from a Linux build. Needed: an AddressSanitizer-like heap and stack checker in the sysroot (even a guard-page allocator with free-list poisoning and a null page) so `compare: "raises"` could cover use-after-free, double free and null reads.
- C++ runtime: when clang can see the UB (a null pointer inlined into a dereference, `*std::unique_ptr` known empty), it emits `unreachable` and the case crashes, but the same code behind a non-inlined call returns 0. Crash or no crash depends on inlining, so authors must never use `compare: "raises"` for UB; worth a sentence in AUTHORING's C++ addendum.
- C++ runtime: pointers are 4 bytes (wasm32), so `sizeof(void*)` is 4 and `sizeof(std::vector<double>)` is 12, against 8 and 24 on a 64-bit desk; lessons that print sizes or addresses have to say so. Printed stack addresses are near 0x7fffe0 because of `--stack-first`.
- C++ code widget: there is no built-in leak check. Level 2 hides a counting `operator new[]`/`operator delete[]` replacement in the `prelude`, whose static destructor exits with status 1 when a block was never `delete[]`d (this also catches `delete` on `new[]` memory). A widget option such as `"leakCheck": true` that does this for `new`, `new[]` and `malloc` would save authors copying 25 lines.
- C++ code widget: function-mode tests cannot check a learner's signature (by value against `const&`) except by a `static_assert` in the `postlude`; clang's message then quotes the whole `std::is_same<...>` before the author's text. A `"signature": "double total_value(const std::vector<double>&, const std::vector<double>&)"` field that the harness checks with its own readable message would help.
- graph canvas: `nodeRadius` sets both the circle size and the frame padding (`r + 26` horizontally, `r + 22` vertically), so a graph with one long rect label and `height` near 200 squashes the nodes into a thin band; level 2 sets `nodeRadius: 20` and `height: 220` to 240 everywhere. Padding should follow the actual node extents.
- manipulate widget: it is not counted as a canvas-bound widget for `explore` screens, so a stepped call stack (array canvas in stack mode, patched by each state) has to be a `problem` screen.
- console canvas: lines wider than about 54 characters scroll sideways with no visual cue, which hides the end of compiler and sanitiser messages; real clang and AddressSanitizer lines are 60 to 90 characters, so authors trim them by hand. A `wrap: true` option (with a hanging indent) would let real tool output be shown verbatim.

Raised later (cpp-pricing level 2):

- C++ code widget: `isclose` is fixed at a relative 1e-9 and cases take no `tol`, so "to 1e-6" or "within 0.005 of 10.45" tests must be written as `std::abs(x - v) < tol` with `expect: true`, whose failure reads only "Expected true, got false". Needed: `tol: { "abs": x }` / `{ "rel": r }` on C++ (and Python) cases, shown in the row.
- series canvas sim: `running: "mean"` has no error band, so a Monte Carlo convergence chart cannot show ±2 SE live; cpp-pricing l8 draws the band from precomputed C++ values as two extra dashed series, and the explore's live line uses the browser RNG, not the C++ stream. Needed: `band: 2` on a running-mean sim (mean ± k·sd/√i, shaded).
- graph canvas: a recombining lattice (binomial tree) has to be hand-placed node by node, and two-line rect labels ("£112.24\n17.71") crowd at n = 3 even with `height: 370`; the `tree` canvas cannot recombine. Needed: a lattice layout (`layout: "lattice"`, `steps: n`) or a `tree` option to merge equal nodes.
- playthrough tool: in one run, `--set cpp-pricing/review-2` straight after four C++ lessons reported "the set has no items" and the homework timed out in `waitForFunction`; the same sets passed when rerun alone. Possibly a load race (other agents writing the course folder) or state left by the C++ worker; worth a retry or a clearer message.

Raised later (stat-learning level 1):

- plane: no way to let a control choose between precomputed curves (one fitted polynomial per degree). Worked round with a ternary chain in one `expr` (`d < 0.5 ? (...) : d < 1.5 ? (...) : ...`). It works, but each function's formula grows to kilobytes: `stat-learning/l3-bias-variance.json` (20 curves × 10 degrees) is 140 KB. Wanted: a function entry with `exprs: [...]` indexed by a param (`"index": "d"`), or `hide`/`show` bindable to a param.
- plane: point sets cannot be shown or hidden by a control. Revealing the held-out set in a second colour had to wait for an `explain.canvas` patch. Wanted: a `hide` list a control or `derive` can set, or a point `visible` expression.
- plane: function labels avoid curves and axes but not points, so "fitted polynomial" and "true line" are drawn over scattered data in l1, l2 and l3. Wanted: labels that also keep clear of points.
- series: a marker label at the last index collides with that series' direct end label (l2 "More data": "80.15" was drawn over "test MSE, 30 days"). Worked round by dropping the marker. Wanted: marker labels placed clear of the series end labels.
- validator: an `explain.canvas` holding a whole canvas (`{ kind, params, state }`) instead of a state patch is ignored without a warning, so the Why? sheet silently shows the unchanged canvas. Wanted: a validator warning when `explain.canvas` (or a `wrong[].canvas`) has a `kind` key.

Raised later (cpp-pricing level 3):

- C++ code widget, script mode: a `stdout` case compares the whole output and stderr is shown only when a run fails, so a graded program cannot also print timings for the learner to read. cpp-pricing l9 uses function mode instead. Needed: a stdout case that checks only matching lines (`match` regex or `lines: [..]`), or stderr shown under passing rows.
- C++ runtime: the optimisation level is fixed at `-O1` and cannot be set per widget or case (the worker's `init` already takes an `opt` knob the page never sends). A widget `flags`/`opt` field (`-O0`, `-O2`, `-DNDEBUG`, `-ffast-math`) would let l11 show debug against release, `NDEBUG` and `-ffast-math` live in the browser instead of through desk consoles.
- C++ runtime clocks: in Chromium `steady_clock` moves in 100 µs steps (`performance.now()` is coarsened because the app is not cross-origin isolated) and `system_clock` in 1 ms steps (`Date.now()`). Serving the app with COOP/COEP headers would give about 5 µs; until then timing lessons must batch work (l9 teaches it as the edge case).
- C++ code widget: `prelude` is per widget, not per case, so "the learner's test must fail against version A and pass against version B" needs every hidden pricer behind a function pointer that each case's `setup` swaps. A per-case `prelude` (or `defines: { "BUGGY": 1 }` compiled once per distinct set) would make planted-bug tests simpler and closer to real code.
- C++ code widget: there is no shared test kit. l12 and homework-3 copy a 25-line `TEST`/`CHECK`/`CHECK_CLOSE` registry into each prelude and a `run_tests()` into each postlude; `cpp` l18 will need the same. A built-in option (`"testkit": true`) or a shared include file would remove the copies.
- series canvas: x is the array index only, so time against n = 100, 200, 400, 800 is drawn on an "n ÷ 100" axis with markers placed by `y` (same need as stat-learning's `xValues` bullet).
- grid canvas: `state.paths` draw their dots and lines through the cell centres, over the cell text, so a route across numbered cells hides the numbers it passes. l10 uses shaded sets instead. Paths could offset below the text, or the text could get a halo.
- boxes canvas: with four `box` containers of three `card` items, card labels shrink until "→ row 0" shows as "row"; l10 uses "→0". A minimum label size (wrapping containers to a second row) would keep labels legible.

Raised later (stat-learning level 3):

- validator vs README-B: plane `heat` function entries (integration pass 5) are rejected like `contour` ("a function needs expr, ..."). l11 wanted the model's default probability as a heat map behind the moving decision boundary; it was dropped. Either accept `heat` (and `contour`) or remove them from README-B.
- plane: no classified-region layer, so a k-NN decision region cannot be filled. l11 draws the 1-NN boundary as 335 marching-squares `segments` computed offline. Wanted: a grid layer (`cells: { x, y, values }`) or a `heat` whose expression can read a precomputed grid.
- plane: a point with `on` can ride only a function, not a polyline of `segments` or a list of points, so the ROC point cannot be dragged along the empirical curve. l12 moves it with a slider over a threshold index and `derive` reading arrays in params. Wanted: `on` a points list (piecewise linear) or a `polyline` function entry.
- controls: no categorical control. l13's model switch is a 0-to-1 slider whose readout shows "0" and "1", with the model's name only in a ternary caption. Wanted: `options: ["logistic", "k-NN, k = 3"]` on a control, binding the index.
- series: lines cannot be shown or hidden by a control, and `reveal` applies to every series at once. l14's P&L explore wanted "toggle costs on" and "add the coin" steps. Wanted: `hide` bindable to a control (one more vote for the stat-learning level 1 request for plane points).
- code widget (Python): `isclose` is fixed at rel 1e-9, so scikit-learn outputs are rounded to 4 places in each call and a value on a rounding boundary could fail across platforms (none did in Pyodide). One more vote for per-case `tol` (raised for C++ in cpp-pricing level 2).

Content note (cpp-pricing): level 2 names its payoff classes Call/Put and level 3 CallPayoff/PutPayoff; the cpp course never teaches inheritance, so cpp-pricing l5 teaches virtual functions from scratch. The topic 1.9 second reader should check the handover and decide whether cpp level 3 needs one screen on inheritance and `virtual`.

Raised later (ensembles level 1):

- tree canvas: `state.collapse: [""]` (collapsing the root, to show depth 0) throws `ReferenceError: Cannot access 'b' before initialization` in `tree.js` `place()`: the fallback `top + b / 2` reads the `const b` declared later in the same function. l1's growth slider starts at depth 1. Fix: rename the inner `b`.
- tree canvas: node labels are params only; no state patch changes a node's pill text. A decision tree cannot show an inner node's question while expanded and its counts while collapsed. l1 and l3 put counts in pills, questions on branch labels (`p`) and predictions in values. Wanted: `state.labels: { "<path>": "text" }`.
- validator: a `tap-regions` answer naming a plane polygon is rejected ("region is not on the plane canvas"), although the engine makes polygons tap targets (pass 5). l1 wanted "tap the leaf rectangle the new loan lands in"; it asks for the training loans in that leaf instead. The validator should collect `state.polygons` (and area) ids.
- controls: no categorical control, again. l3's "Tree (1: depth 1, 2: depth 3, 3: unlimited)" and l4's leaf-size "Setting" sliders show indices, with the meaning only in the caption. One more vote for `options: [...]` on a control.
- plane: no step-function entry. l3 and l4 draw leaf rectangles and regression-tree steps as precomputed `polygons` and `segments` per setting, swapped by `derive` reading arrays in params. Wanted: a `steps` function entry (breakpoints and levels, closed and open ends) that a slider could switch.
- tree canvas in a stacked `pair`: on two depth-2 trees with long branch labels, labels of neighbouring subtrees sit close (l3 bootstrap pair, "leverage > 3.56" just above "leverage ≤ 4.62"). Readable, but a little more label spacing would help.

Raised later (cpp level 3):

- C++ runtime (precompiled headers): once the builder has made a PCH for a unit's leading `#include` lines, an `#include` of any other header later in the unit fails, for example in the `postlude` after the learner's code. The message is `fatal error: cannot open file '/usr/include/c++/v1/cstdint': Out of memory`. The same source compiles without the PCH, so the failure depends on timing: cpp l12 screen 8 passed alone and failed after earlier lessons. Workaround used: every header the postlude needs goes in the prelude's leading includes. Needed: the worker's file system in PCH mode should serve the full header tree, or the worker should retry without the PCH on such an error. Until then, a line in AUTHORING's C++ addendum.
- validator: a C++ case whose call returns `std::string` text that looks like a number (`Fixed<2>::from_units(1234).str()` expecting `"12.34"`) warns "expect is the text ...; a number is written without quotes". The warning cannot know the return type. It should be silenced by a per-case flag such as `"text": true`, or worded as a question.
- C++ runtime: there is no unwinder, so `catch` never runs. Invariant lessons therefore cannot show the caller recovering from a refused operation, or test the strong guarantee (a refused `sell` leaves the position unchanged, checked after the catch). Tests can only check that the program stops (`raises`). Needed: libunwind (or the wasm exception-handling proposal) in the sysroot.
- C++ code widget: there is no "must not compile" case. A `private` member written from outside, `Pnl + Quantity`, a deleted copy and a missing `const` can only be shown in `console` canvases. A deleted copy alone can be tested, through `std::is_copy_constructible_v`. Needed: a case shape such as `{ "compiles": "Connection b = a;", "expect": false }`, compiled as an extra snippet after the learner's code, with the first `error:` line shown.
- boxes canvas: `card` items with code labels (`set_bid(b)`, `spread()`) in a container with several cards per row are drawn narrower than their text, so the label touches or overflows the card edge. cpp l10 used `cols: 2` and shorter labels. Card width should come from the measured label in the code face.
- C++ code widget: learner code is compiled without `-Wall`, so `-Wreorder-ctor`, `-Wuninitialized` and `-Wreturn-stack-address` never appear under the editor. cpp l11 teaches member initialisation order through a `console` of clang `-Wall` output instead. Needed: `-Wall` by default, or a widget field such as `"warnings": ["-Wall"]`.

Raised later (fin-ml level 1):

- series: only markers are tap targets. "Tap the barrier hit first" (fin-ml l2) puts marker dots on the barrier lines, because `hlines` and the `window` cannot be tapped. Wanted: `hlines` ids and the `window` as tap targets.
- series: no vertical reference line. The triple-barrier time limit is drawn as the right edge of `window`. Wanted: `vlines: [{ id, i, label }]`, as plane has, patchable so a slider on h can move it.
- graph: with `shape: "rect"` nodes, directed edges showed no visible arrowheads at 1280 or 390 px, and `bend` on an edge passing behind a middle node drew it straight through that node (fin-ml l3's two-stage picture; the edge was dropped and the layout changed). Worth checking arrowheads on rect nodes and `bend` on straight runs.
- no canvas for overlapping intervals over a day axis. fin-ml l4 draws label windows as plane `segments` in a stacked `pair` with an `array` of days; the array takes only one `highlight.range`. Wanted: `highlight.ranges: [...]` on array, or a timeline kind (rows of intervals over tappable day cells).
- code widget (Python): `isclose` is fixed at rel 1e-9, so scikit-learn probabilities are tested with `bool(np.allclose(..., atol=0.002))` calls whose failure shows only "False". One more vote for a per-case `tol`.

Raised later (cpp level 4):

- C++ code widget: there is no test framework and no `try`/`catch`, so writing tests needs a hand-made stand-in in the prelude. Level 4 hides about 25 lines: `TEST(name)`, `CHECK`, `CHECK_CLOSE`, a registry, and a postlude `main` that prints `N passed, M failed`. Planted bugs are chosen by a number on `stdin`, which prints `planted bug k: caught/missed`. Needed: a shipped header-only test kit (`"testKit": true`) and a way to run the learner's tests against planted variants without routing through `stdin`, as the pytest course's `outcome(planted)` does. `REQUIRE_THROWS`-style tests stay impossible until the sysroot has an unwinder.
- C++ code widget, script mode: stderr is never shown for a run that exits 0, so the stand-in's per-check detail (`line 12: CHECK_CLOSE(...) failed`) is invisible exactly when a learner needs it. The detail cannot go to stdout, because the case compares the whole of stdout. Needed: stderr shown, folded, under a failing stdout row, or a compare mode that checks only the last line.
- C++ code widget: function-mode `call` expressions that end in a member access or index on a returned temporary (`sort_book(...)[0].price`, `price_lattice(...)[3]`) return a dangling reference through the harness's `decltype(auto)`, giving garbage or "memory access out of bounds". Authors must use `setup` (`auto b = ...;`) first. The harness could decay the result (`auto v = expr;`) when the expression is not a plain call, or AUTHORING could say so.
- C++ code widget: there is no way to compile several translation units, so separate compilation (header, `.cpp`, linker) is simulated by putting the header in the `prelude`. A real "two files, one link" exercise, such as a `files: { "rates.h": ..., "main.cpp": ... }` option, would let l17 show a genuine multi-file build.
- Why sheet (explanation copy) with `derive`: an `explain.canvas` that changes a derived parameter (`params.n` 3 to 5 on the l14 array explore) was drawn mid-tween. The caption and cells showed n = 5, but the derived `active` and `done` showed n = 4. l14 now repeats every derived key in the explain patch. The copy should run derive on the final state, or apply the patch instantly.
- array canvas: a cell count that grows through `derive` (cells from 4 to 8) was laid out on two rows in the Why sheet without `wrap`, with the caption on top of the second row. l14 now keeps the length fixed and dims unused slots with `active`. Layout should follow the current number of cells.
- boxes canvas: cards in a `row` container keep the width of a slot, not of their label, so "BARC −200" overflows its slot (l15 hook). Labels were cut to the keys alone. Row slots should take the widest card's width, as other containers do.

Raised later (validation level 2):

- No time-line canvas for folds. validation l5 and l6 use a one-row `grid` (15 day cells, or 6 blocks), whose cells shrink to about 18 px at 390 px wide, too small to tap reliably. `array` has only one `highlight.range` and no per-cell colour, so it cannot show train, test, purge and embargo at once. Wanted: a timeline kind (a row of wide cells or ranges over a day axis, shade sets per role, hatched purge and embargo, tappable cells), which would also serve fin-ml l4.
- Stepping a canvas through authored states needs nested ternaries in `derive` (`"shade.test.ids": "fold < 1.5 ? [...] : fold < 2.5 ? [...] : ..."`, one for train, test and caption each). Wanted: a control that selects one of a list of authored state patches (`"frames": [{...}, ...]`, bound to a slider), so "slide through the folds" is data, not expressions.
- plane `segments` are not tap targets. The l7 overlap picture makes each row a tappable dot beside its label bar; tapping the bar itself (the label window) is the natural action. Wanted: segments (and polygons already are) in tap mode.
- number-line has no zoom or scale break: a 5-row `gap` on a 0 to 1,000 axis draws as a dot between the train and test intervals (l6). Wanted: a zoom inset or `state.view` as plane has.
- Python code widget: `isclose` is fixed at rel 1e-9, so scikit-learn scores are rounded to 4 places in the call and compared exactly; a platform difference in the fifth place would flip a rounding digit. Another vote for a per-case `tol`.

Raised later (fin-ml level 3):

- longform widget: rejected in lesson files ("longform belongs in homework and exams"), so l12's "draft the what-failed paragraph against a rubric" became a `multi` that picks good sentences. Wanted: a self-marked draft widget for lessons (free text, then the rubric and a model paragraph, ungraded for progress).
- series canvas: series values are fixed arrays, so a cost slider cannot redraw cumulative net P&L live (net_t = gross_t − c·traded_t); l10 shows total net P&L against cost on a `plane` instead. Wanted: a series whose values are an expression over data arrays and params (`values: { "expr": "gross - c * traded", "data": {...} }`), or derive writing whole series.
- plane canvas: no `xScale: "log"`, so the DSR against the number of trials could only be drawn for N = 2 to 30; N = 1 to 1,000 went to a `bars` chart. Wanted: log x on plane, as series and number-line already have.
- curve formulas and derive: `Phi` exists but no inverse; l11's DSR and E[max] curves inline a 300-character Abramowitz-Stegun approximation (error about 4.5e-4). Wanted: `PhiInv(p)` (and `NormInv`) in curve formulas and derive.
- table widget: `bind` reaches tree branches and grid cells only, so values a learner types (three Sharpe standard errors) cannot draw on a bars or plane canvas as they type. Wanted: `bind: "values.<category>"` for bars and `bind: "points.<id>.y"` for plane.
- Python code widget: another vote for a per-case `tol`; the scikit-learn study is compared after rounding to 4 places with `isclose` at 1e-9, so a fifth-place platform difference would flip a digit.
- graph canvas: rect nodes with labels of about 18 characters overlap at four per row in the 540 px column (labels are clipped, "dels and trial log"), and the frame does not widen or warn; l12 uses three per row. Wanted: node spacing checked against measured label widths, or automatic wrapping.

Raised later (validation level 3):

- sim outcomes (bars and series `sim`): `max` and `min` are `Math.max`/`Math.min` and take no list, so `max(sample(N, n()))` is not possible. The best of 40 had to be written as 40 copies of the term (2 KB outcome strings in l12) and no slider can change N. Wanted: list-aware `max`/`min` (and `argmax`), so a best-of-N simulation follows a control on N.
- expression widget: Compute Engine parses a capital `N` as its built-in numeric-evaluation function, so an answer such as `\frac{\sqrt{2\ln N}}{\sqrt{T}}` never grades as correct (the playthrough reported "not correct, key null"). l12's derive became an `order` item. Wanted: treat lone single letters as symbols in the grader, or a validator warning for `N` (and other CE built-ins such as `D`, `E` used as variables).
- bars canvas: with `showValues`, a bar of height 0 shows no value label, so "the scaling leak is 0.00" was invisible; l10 adds a caption. Wanted: a value label at the baseline for zero bars.
- graph canvas: directed edges between `rect` nodes spaced about a node-width apart show no arrowheads (the edge stops at the rims with no room), so a pipeline's order is not readable; l10 numbers the steps in their labels. Wanted: a minimum edge length or arrowheads drawn on short edges.
- number-line canvas: plain points with near-equal values (seven training days between 19 and 27 on a 10 to 70 axis) draw on top of each other with no stacking or jitter. Wanted: `stack: true` to lift coincident dots, as labels already stack.

Raised later (ensembles level 2):

- plane canvas: `heat` and `contour` take only an expression, so a fitted model's decision regions cannot be drawn. The brief's picture, a wiggly single-tree boundary against the smoother forest boundary over class points, was dropped from l5 and l6 (dozens of hand-made polygons per tree would be needed). Wanted: a region map from data, either `heat` over a lattice of values (`{ "grid": { "x": [..], "y": [..], "values": [[..]] }, "colours": {...} }`) or a list of axis-parallel rectangles with a class colour each, plus per-point colours for the class dots.
- tree canvas: an internal node shows only its question pill, so l8 screen 1 had to put each split's Gini drop (0.120, 0.040, 0.020) in the caption. Wanted: per-node annotations (`state.notes: { "y": "ΔGini 0.040" }`) and row counts beside internal nodes, which would also serve ensembles l1 to l4 and boosting.
- series canvas: x is an index (or dates), so a curve sampled at B = 5, 10, ..., 150 cannot be drawn at its true positions; l7 had to fit all 150 forests to fill every index. Wanted: numeric x values (`x: [5, 10, ...]` per series), as `bars` has `xAxis: "value"`.
- Python code widget: another vote for a per-case `tol`. Accuracies are rounded to 4 places and compared at rel 1e-9, and matching scikit-learn's `permutation_importance`, which shuffles with its own generator, needed a boolean case (`abs(mine - ref) < 0.01`) instead of a tolerance.

Raised later (fin-ml level 2):

- series: a slider cannot choose which data a line shows. fin-ml l6's "difference at d" slider preloads 11 series (d = 0, 0.1, ..., 1) and derives `hide` from `d` with `ids.slice(0, k).concat(ids.slice(k + 1))`. It works, but it multiplies the JSON and every hidden series still sets the y range and the label margin.
