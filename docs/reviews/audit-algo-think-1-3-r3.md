1. `l6-call-stack.json` | `screens[3].widget.options[1].why`, `screens[3].feedback.byKey.limit`, `screens[7].widget.options[1].why` | imprecise, minor | The three lines say a high recursion limit lets the real stack overflow and Python "can crash with no traceback". For the functions on these screens that is not true of standard Python 3.11 or later, nor of the page. | With `sys.setrecursionlimit(10**9)`, `sum_to(5000)` returns 12,502,500 on CPython 3.11, 3.12 and 3.13 and in Pyodide 0.27.7; `sum_to` runs 3,000,000 deep on CPython and 2,000,000 deep in Pyodide. Basis: What's New in Python 3.11, "Inlined Python function calls": pure-Python calls no longer use C stack. The library reference for `sys.setrecursionlimit` still warns that a too-high limit can lead to a crash, so the lines repeat the documented caution; they are dated, not invented. The options stay wrong answers to "work safely", since memory still grows with depth. | Paste: `screens[3]` why: "It runs in Python 3.11 and later, but every waiting call still holds a frame, so memory grows with `n`.
