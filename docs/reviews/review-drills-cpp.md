# Drills pack `cpp`: second-reader findings

Scope: the 25 files `app/content/drills/cpp-*.json` with `"pack": "cpp"` at commit 3bd2824 (17 for `cpp`, 8 for `cpp-pricing`), against `docs/briefs/drills-1.1-1.9.md`, `docs/briefs/drills-1.8.md`, `docs/briefs/drills-ci-packs.md`, AUTHORING section 3 (C++ runner) and section 5 "Drill".
Method: as `review-drills-py.md`. I read each drill as a learner of topic 1.9 (brief, constraints, examples), then wrote my own Python model of all 25 from the briefs alone (`mine.py`: Fractions, mpmath at 40 digits, a node recursion for the tree, counting for ranks, a regular expression for the fills file). I read every model `solution` as C++ and ran all 25 under AddressSanitizer and UBSan. I wrote 30 wrong candidates the author did not plant, at least one for every drill, one correct but slow one, and two probes that keep to the brief (`wrong/`). All ran natively on every hidden test, each case in its own process, under a copy of the page's comparison (`harness.py`). The 17 that passed natively were then run in the app's own runtime (clang 21 to WebAssembly) through `planted-check.mjs` on a copy of `app/` (`app_probe.py`), first with the committed tests and then with the tests proposed below. For level I opened the named lessons, the level reviews and the homework (`first_taught.py`, `lesson_tasks.py`). I read every `notes`, `hint`, `how` and `slip` line against the model.
Compiler: g++ 13.3.0 (`-std=c++17 -O1`, as the runner's `-std=c++17 -O1`), with clang++ 18.1.3 on libstdc++ as a second native compiler. No native libc++ is installed, so anything that turns on libc++ or on 32-bit `long` was settled in the app's runtime.
Scripts: `docs/reviews/drills-cpp-scripts/` (from the repo root; `mine.py` and `gen_extra.py` need the scratchpad venv Python): `harness.py model|san|wrong|extra|show <id>`, `mine.py`, `gen_extra.py` (writes `extra_tests.json`), `app_probe.py <copy> <pkgs> before|after <ids>`, `first_taught.py [grep <token>]`, `lesson_tasks.py [-v] <course>/<file>`, `repeats.py`.
Format: `N. file | JSON path | tag | what is wrong | exact fix`. Tags: `wrong` = a learner is marked wrongly or told something false that costs them; `weak` = the tests miss a real wrong solution, or the statement is ambiguous; `minor` = otherwise.
