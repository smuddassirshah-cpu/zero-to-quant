Method. Each changed item was read whole as it stands (`brief.py`, `near.py`), the renumbered ones solved by hand from the text before the key was read. `recompute.py` recomputes every changed key, `wrong` value and printed number by two routes (exact fractions or sympy; floats, NumPy, `expm`, `quad`, a count or an Euler scan). It checks each key band takes the key and its honest roundings, refuses the neighbours and every `wrong` value, that no two bands of a part meet, and that each slip follows from the working its line names. For part C it lists the workings a candidate might use and which the wider band takes. `grade.mjs` types 493 answers (949 checks with the stored values) into the engine's own graders (`numGrade`, `numSetGrade`, `exprGrade`), with and without units. `fresh.py` greps every string of every content file for the new numbers and settings (DECISIONS session AB), and each renumbered item for its old numbers. No browser and no playthrough were run.

Scripts: `docs/reviews/review-delta-ac-3-scripts/`, run from the repo root with the scratchpad venv Python: `brief.py <file> <id ...>`; `near.py <file> <key or wrong id>`; `at.py <file> <path>`; `dump.py`; `recompute.py [--show]`; `grade.mjs --local-cdn <pkgs> [--show]`; `fresh.py [--show]`.

Tags: `wrong` = a learner is marked wrongly or told something false; `unclear` = a statement reads two ways; `minor` = otherwise.
