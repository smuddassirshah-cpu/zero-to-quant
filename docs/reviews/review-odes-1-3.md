Format: `path | screen/item | severity | what is wrong | fix`. Severity: error = wrong number, false claim or wrong grading; warning = weak explanation, mis-diagnosing distractor or teaching issue; note = style. Old strings are quoted as they appear in the JSON source (backslashes doubled).

## What the author's scripts do not check

- They never open the content files: each `check()` compares a hard-coded "stated" value with two computed routes. A number typed differently in the JSON, or a number missing from the script, passes unseen. Example: l9's "0.198" is not in the L2 script and is wrong (below).
- They do not check that a distractor value matches its `why` or `byKey` text, nor tolerance overlaps or tolerances against the precision a question asks for.
- They do not check qualitative claims (quantifiers, "any nudge", "all paths").
- Code tests are left to the playthrough; I re-ran them locally (all green, see the end).
