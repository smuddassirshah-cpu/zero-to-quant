# Drills pack `ci`, pack 6 (one-dimensional dynamic programming): second-reader findings

Scope: the 15 files `app/content/drills/ci-*.json` tagged `pack-6`, at commit 2567918, with `docs/reports/drills-ci-6.md` and `docs/reports/drills-ci-6-check.py`, against `docs/briefs/drills-ci-packs-5-8.md`, `drills-ci-packs.md`, `drills-1.8.md` and AUTHORING section 5.
Method: as `review-drills-ci-5.md`. I read each drill as a candidate (brief, constraints, hint, examples) and wrote my own solution to all 15 before reading any model (`mine.py`), by another method where one exists. I ran mine and the model on every example and hidden test, then model, mine and a brute force of my own against each other on 6,000 small random inputs a drill, and model against mine on 300 larger ones (`checks.py random 6000`). I evaluated the real arguments of all 226 calls and tested them against the prose constraints, the generated calls included (`checks.py constraints`), and read the `constraints` objects against the prose. I wrote 61 candidates the author did not plant (`wrong.py`, three to six a drill) and ran them natively; every one that passed was searched for a small counterexample (`counter.py`) and run again in Chromium and Pyodide through `planted-check.mjs` on a scratch copy of `app/` (`pyodide_probe.py`). `extra_checks.py` computes each proposed test with the model and with mine and shows what each candidate returns. I read every `notes`, `hint`, `how`, example `note` and `slip` line against the model, and compared each drill with the `coding-int`, `trees` and `contests` code tasks and the `dsa-`, `oa-` and earlier `ci-` drills.
Scripts: `docs/reviews/drills-ci-6-scripts/` (from the repo root, with the scratchpad venv Python: `harness.py mine.py app/content/drills`, `harness.py wrong.py app/content/drills --limit 15`, `checks.py app/content/drills [constraints] [random N] [planted]`, `counter.py app/content/drills [label ...]`, `extra_checks.py app/content/drills`; proposed tests in `extra_tests.json`).
Format: `N. file | JSON path | tag | what is wrong | exact fix`. Tags: `wrong` = a learner is marked wrongly or told something false that matters; `unclear` = the statement leaves a graded case open; `weak` = the tests miss a real wrong or too-slow solution; `minor` = otherwise.
