# Drills pack `dsa`, sub-packs A and B: second-reader findings

Scope: the 30 files `app/content/drills/dsa-*.json` (A: hashing, prefix sums, simulation; B: two-pointers, windows, stacks-queues, binary-search), against `docs/briefs/drills-1.8.md`, AUTHORING section 5 "Drill" and "Exam freshness", and the authors' reports `docs/reports/drills-dsa-a.md` and `-b.md`.
Method: I wrote my own solution to every drill from its `brief`, `constraints` and examples only, before reading the model `solution`, and ran it on every example and hidden test (`mine_a.py`, `mine_b.py`). For each drill I planted three wrong solutions: an off-by-one or boundary slip (`wrong_*1.py`), a tie, duplicate or ordering slip (`wrong_*2.py`), and the slow method the constraints name (`wrong_*3.py`, stopped at 5 s natively). `extra_checks.py` holds the wrong solutions that pass every test and computes each proposed new test with my solution and the model. I read both authors' check scripts, judged their slow methods, and ran a voice scan and a freshness grep of `ds`, `algo-think`, `graphs-dp`, `coding-int` and `drills`.
Scripts: `docs/reviews/drills-dsa-a-b-scripts/` (run `harness.py <module> app/content/drills` and `extra_checks.py app/content/drills` with the scratchpad venv Python).
Format: `N. file | JSON path | severity | what is wrong | exact fix`. Severity: error = wrong test, wrong example or a statement that teaches something false; warning = ambiguity, a test gap or a binding-rule breach; note = otherwise.

## Tool results

- My own solutions: 30 of 30 drills pass every example and hidden test (A 15/15, B 15/15). No brief was misread in a way the tests punish, and no test or example `expect` is wrong.
- Planted off-by-one and tie solutions: caught in 28 of 30 drills. Not caught: `dsa-varied-windows` (finding 3) and `dsa-closest-hedge` (finding 6). `dsa-net-tape` catches FIFO netting only with its last large test (finding 5).
- Planted slow methods: caught by the large tests in 29 of 30 drills (each ran past 5 s natively, so well past it in Pyodide). Not caught: `dsa-kiosk-spacing` (finding 4).
- `docs/reports/drills-dsa-a-check.py`: exit 0, `errors: 0`. `docs/reports/drills-dsa-b-check.py`: exit 0, `15 drills, 0 errors`.
- Voice: `voice-scan.py 35` on a copy of the 30 files: 840 sentences, 0 over 35 words, 0 explanations over three sentences. No exclamation marks, em-dashes or en-dashes; no American spellings found.
- `index.json` rows match `name`, `course` and `difficulty` for all 30; every `skills` entry is declared by a lesson of the drill's `course`. Difficulty mix 5 / 6 / 4 per sub-pack; three `stdin` drills per sub-pack.
- I did not run the validator or the playthrough (both write files, and this pass only reads); the authors report both green.

## Findings

1. app/content/drills/dsa-net-tape.json | notes[1] | error | "once it rests as a negative it shields older buys from every later sell" is false. A sell rests only when no buy is left, so the resting list is always sells then buys, and no older buy ever sits under a resting sell. The note teaches a case that cannot occur. | "A sell may use several buys. It rests only once every buy is gone, so later buys stack above it and never reach it."
2. app/content/drills/dsa-sensor-alarm.json | notes[1], hint | error | "dividing whole numbers would round away a near miss" is false here. For a whole `t`, `s // k >= t` holds exactly when `s >= k * t`, and `s / k >= t` gives the same answer for every input in range (the float error is far below the 1/k gap). Both division versions pass all 14 cases (`extra_checks.py`). The advice stands; the reason does not. | notes[1]: "The average must be at least `t`, so compare `sum >= k * t`. Whole numbers keep the test exact, with no division to think about." Hint, first sentence: "Compare the window sum with `k * t` instead of dividing, so the test stays in whole numbers."
3. app/content/drills/dsa-varied-windows.json | tests | warning | A solution that counts a window when its first and last badge differ passes all 14 cases. Every repeat in the tests sits at both ends of a window, or every window repeats. | Add two tests (expects from my solution and the model): `{"call": "count_varied_windows(['a', 'b', 'b', 'c'], 3)", "expect": "0", "compare": "equal"}` and `{"call": "(lambda b: (b.__setitem__(50000, 49990), count_varied_windows(b, 30000))[1])(list(range(100000)))", "expect": "40011", "compare": "equal"}`. 4. app/content/drills/dsa-kiosk-spacing.json | tests[10], tests[11] | warning | The constraint says "Trying every gap in turn is too slow", but trying every gap from the even split `(max - min) // (k - 1)` downwards passes both large tests in 0.04 s.
