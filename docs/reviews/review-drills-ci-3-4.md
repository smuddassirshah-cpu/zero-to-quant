# Drills pack `ci`, packs 3 and 4: second-reader findings

Scope: the 30 files `app/content/drills/ci-*.json` tagged `pack-3` (stacks and queues, binary search) or `pack-4` (trees, heaps and tries), at commit 99b7aa7, against `docs/briefs/drills-ci-packs.md`, `docs/briefs/drills-1.8.md` and AUTHORING section 5 "Drill".
Method: as `review-drills-ci-1-2.md`. I read each drill as a candidate (brief, constraints, examples), then wrote my own solution to all 30 by a method other than the model's wherever one exists (`mine.py`). I wrote 50 wrong or too-slow candidates the authors did not plant, at least one a drill (`wrong.py`), and ran them on every example and hidden test in CPython with a 5-second limit for the whole run. Candidates that passed were run again in the real runtime (Chromium and Pyodide, through `planted-check.mjs` on a scratch copy of `app/`; `pyodide_probe.py`). `extra_checks.py` computes each proposed test with the model and with my solution and shows what each candidate returns. I read every `notes`, `hint`, `how` and `slip` line against the model, and compared each drill with the `dsa-`, `oa-` and other `ci-` drills.
Scripts: `docs/reviews/drills-ci-3-4-scripts/` (from the repo root, with the scratchpad venv Python: `harness.py <mine.py or wrong.py> app/content/drills`, `extra_checks.py app/content/drills`, `time_live_median.py`; proposed tests in `extra_tests.json`).
Format: `N. file | JSON path | tag | what is wrong | exact fix`. Tags: `wrong` = a learner is marked wrongly or told something false; `weak` = the tests miss a real wrong or too-slow solution, or the statement is ambiguous; `minor` = otherwise.
