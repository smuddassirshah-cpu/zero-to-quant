1. l16-interpolating.json | quiz[3].explain.text and screens[6].feedback.byKey.dates | imprecise | "Only `method="index"` or `"time"` uses the stamps as the x values" (and "Without `method="index"` or `"time"` the stamps are ignored") is false as an "only": a learner carries away that every other method fills by position. | pandas `Series.interpolate`: `linear` is the one method documented to ignore the index; `values` is an alias of `index`, and the scipy methods `slinear`, `polynomial`, `nearest`, `quadratic`, `cubic`, `spline`, `pchip`, `akima` all pass the index to scipy. On index [0, 1, 4] with [100, NaN, 112]: `slinear` and `polynomial` give 103, `nearest` 100, the default 106; `time` refuses an integer index (sim: concepts `L16 q16-method`, EXPECTED_FAIL). | quiz[3].explain.text: "The default `linear` ignores the stamps. `method="index"` (or `"values"`, or `"time"` on a datetime index) interpolates on them, as the scipy methods do." screens[6].feedback.byKey.dates: "You trusted the index. The default `linear` ignores it; ask for `method="index"`, or `"time"` on a datetime index."

2. l16-interpolating.json | screens[9].widget.options[ffill].why | misleading | The forward fill is dismissed because it "ignores the later point", which is exactly its virtue for a feature series: linear interpolation at $t$ reads $y_1$ at $x_1 > t$, so a linearly filled price series used as a model input is look-ahead. The lesson never says which fill reads the future, though the course warns against leakage elsewhere. | The formula $y_0 + (y_1 - y_0)(x - x_0)/(x_1 - x_0)$ holds $y_1$; `ffill` reads only the past (sim: concepts `L16 linear fill reads the later point, ffill reads only the past`); LdP ch. 7 on look-ahead in features. | why: "You carried a value forward. That ignores the later point and makes steps, so it is not an interpolator. It is the right fill for a live feature, which cannot see the later point." Also add to summary.trap a second sentence: "A linear fill reads the later point, so never feed it to a model as if it were known at the time."

3. l18-updating-a-fit.json | screens[8].widget.lines[x].text and .why | imprecise | The distractor reads "Subtract $c$ from $y$ as well, so both columns are small" and its why says "That leaves the huge $x^2$ sums". Shifting $y$ in addition to $x$ leaves no huge sum: the fit is exact (slope 0.5), so the step is harmless, not wrong. The why describes shifting $y$ instead of $x$. | Algebra: cov and var are shift-invariant in each column; sim: concepts `L18 derive distractor x` (EXPECTED_FAIL) gives 0.5 exactly with both columns shifted. | lines[x].text: "Subtract $c$ from $y$ instead of $x$, since $y$ is the column being fitted." why unchanged. byKey.x: "You shifted $y$ instead of $x$, which leaves the troublesome $x^2$ sums alone."
