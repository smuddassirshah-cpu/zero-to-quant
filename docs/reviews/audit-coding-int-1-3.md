# Concept audit: coding-int (topic 3.5), levels 1 to 3

Scope: `app/content/courses/coding-int/` l1 to l14, review-1 to review-3, homework-1 to homework-3. Blind read (no earlier review, answer check or author report opened until the ledger and the findings below were committed). Ledger: `docs/reports/audit-coding-int-1-3-ledger.md` (243 rows: 237 correct, 1 wrong, 5 imprecise, 0 misleading, 0 unverified). Scripts: `docs/reports/coding-int-L1-concepts.py`, `-L2-`, `-L3-` (run with `python3 -I` from the repo root).

Method for a code course: every Python and C++ code widget (23 widgets: 19 Python, 4 C++) was run outside the app, the model solution against every hidden test and the untouched starter against the same tests (the solution must pass all, the starter must fail at least one); the C++ widgets were compiled with g++ -std=c++17 through a generated harness that renders the tests' `args` and `types` as braced literals. Every model solution was then compared with an independent reference on random inputs (brute force, a library reference such as `OrderedDict`, `posixpath.normpath` or `statistics.median`, or a second reading of the statement), so a solution that passes its tests by a method other than the one the lesson names would have shown. Every stated trace (deque states, heap pops, running medians, bot trades, order-book fills, cache evictions, limiter decisions), count and complexity ratio was recomputed; complexity claims use operation counters at several sizes (deque pushes and pops at n = 1,000 to 100,000; centre-expansion steps at n = 200, 400, 800; trie node visits with 100 and 4,096 tickers), never timing. Python-behaviour claims (sort stability, dict order, `//` against truncation, `eval`, `str.split`, negative-integer bit operations, missing-argument errors) and C++ claims (lexicographic `std::sort` on nested vectors, `priority_queue` with `std::greater`, `std::list` iterator validity under `splice` and `erase`) were run, not recalled. Conventions (closed against half-open intervals, maker-price fills, amend-up losing time priority, "at least" including equality, a refused request never recorded, an age equal to the ttl expired) were checked against the standard practitioner usage and for being said once where they first matter.

Format: `N. file | JSON path | severity | problem | evidence and basis | exact fix`.

## Level 1

1. l2-prefix-trees.json | screens[9].widget.options[1].why | imprecise | "For 4,000 symbols both are fast, about 12 steps each" gives the trie the sorted list's cost. A trie prefix walk costs one step per letter of the prefix (3 for a 3-letter prefix), which quiz[3].explain of the same lesson states; only `bisect` makes about 12 comparisons. A learner carries away that a trie lookup grows with the number of words. | sim: `coding-int-L1-concepts.py`: `l2 s9 o1.why` (fails by design: the walk takes 3 steps, the check encodes "about 12"); S&W 5.2 (search cost is the key length). | Replace the why with: "For 4,000 symbols both are fast: `bisect` makes about 12 comparisons and a trie walk one step per letter. The trie's dicts cost far more memory."
2. l2-prefix-trees.json | screens[9].explain.text (last sentence) | imprecise | "A trie pays off with many words, frequent inserts or many words per prefix": the third case does not favour a trie. After one `bisect_left` the words with a prefix are contiguous, so listing or counting k of them costs O(log n + k) with a sorted list and O(L + k) with a trie, the same shape. What favours a trie is inserts and removals (one step per letter against shifting a list) and queries that branch, such as the wildcard of homework-1. | derivation (sorted order groups every prefix; `bisect_right(prefix + '￿')` ends the run); S&W 5.2. | Replace the last sentence with: "A trie pays off with frequent inserts or removals, which cost one step per letter instead of shifting a list, and with queries that branch, such as a `?` in a pattern."
3. l5-bit-tricks.json | screens[8].widget.options[3].why (and the prose that frames it) | imprecise | The distractor "Twice the sum of the distinct numbers, minus the sum of all" is rejected with "Finding the distinct numbers needs a set: O(n) memory again". The method is correct (2 x sum(distinct) - sum(all) is the unpartnered number), and a feed's sequence numbers are consecutive 1..N in the usual sense, so the distinct sum is N(N + 1)/2 and the method runs in O(1) memory: a learner who knows the identity is marked wrong for a valid constant-memory answer. | sim: `coding-int-L1-concepts.py`: `l5 s8 o3` (both forms recover the missing number on 100 random feeds). | Add to the prose after "identified by a sequence number": "Sequence numbers restart and skip, so the set of numbers is not known in advance." and change the why to: "That works, but the numbers are not known in advance, so finding the distinct ones needs a set: O(n) memory again."
4. homework-1.json | items[1].prose (last sentence), items[1].explain.text (second sentence), items[1].feedback.byKey.test-9 | imprecise | "Each step must take time in proportion to the length of its argument, not to the number of tickers listed" and "A `?` branches into every child, so the work grows with the question marks, not with the tickers listed" hold for `add`, `remove`, `has` and `longest_listed` but not for `count_match`: each `?` branches into every child, so a pattern of q wildcards visits up to (alphabet)^q nodes, a count that grows with the tickers listed. The performance task's stated requirement is one no implementation can meet, and the explain teaches that wildcard search is independent of the data. | sim: `coding-int-L1-concepts.py`: `h1 i1 prose` (fails by design: `????` visits 4,681 nodes with 4,096 tickers against 273 with 100); without a `?` the walk is 5 visits for `ABCD`. | Prose: "add, remove, has and longest_listed must take time in proportion to the length of their argument, not to the number of tickers listed. count_match may branch at each `?`, but it must never scan every listed ticker." Explain: "A `?` branches into every child, so the work grows with the branches the pattern opens, never with a scan of every ticker listed." byKey.test-9: keep as it is.
