# mock-oa-trader-2 and -3: second-reader findings

Scope: `app/content/exams/mock-oa-trader-2.json` and `mock-oa-trader-3.json` (80 items: per version 15 sequences, 15 probability, 6 rankings and 4 intervals), against version 1 (`mock-oa-trader.json`), `docs/briefs/mock-versions.md`, the author's report `docs/reports/exam-mock-oa-trader-versions.md` and number script `docs/reports/exam-mock-oa-trader-versions-numbers.py`.

Method: I sat both versions blind from `blind.py` (options sorted by text, order lines by id, no keys, feedback or explanations), wrote my 80 answers into `compare.py`, and only then read the keys. I searched every sequence of all three versions for a second rule with `seq_rivals.py`: constant difference, constant ratio, polynomials of degree 2 and 3, linear recurrences of order 1 to 3 with a constant, homogeneous order 2 and 3, geometric differences, arithmetic ratios, two and three interleaved strands, periodic blocks, and 29 filter rules (primes, smooth numbers, squarefree, non-squares, digit properties, semiprimes and so on). `third.py` checks the harder probability items by seeded simulation, recomputes every ranking value shown, and checks every number in the fixes below. Then I read every option, `why`, feedback and explanation.

Scripts (committed): `docs/reviews/exam-mock-oa-trader-versions-scripts/` (`blind.py`, `compare.py`, `seq_rivals.py`, `third.py`, `show.py`).

Format: `n. file | item id | JSON path | severity | problem | fix`.

## Script results

- Blind sitting: **80 of 80** agree with the keys (`compare.py`). There was no disagreement to settle; `third.py` still checks v2 B11, B12, B13, B15 and v3 B15 by simulation (300,000 runs, within 0.005; 40,000 branching runs, within 0.01) and all twelve rankings' printed values. All pass; `third.py` exits 0.
- Author's script, run with the scratchpad venv: exit 0, "80 keys recomputed twice".
- Is its second method independent? Mostly. Probability and ranking keys are checked by enumeration (`product`, `permutations`, geometry from coordinates) or seeded simulation, which is independent of the closed forms. Five "second methods" restate the key: v2 `a15` (`lambda a: 13 * 17`), v3 `a02` (`F(6, 13)`), v3 `a12` (`3 + 1`), v3 `a15` (`216 ** 2`), and v2 `b01` (counting 6 in `[1, 2, 3, 4, 5, 6, 6]`). Its sequence rival check tries only the version 1 rule families, which is why it missed findings 1 and 2.
- Voice: `voice-scan.py 35 --summary` on the two files: 0 sentences over 35 words, 0 explanations over three sentences. My own scan: no exclamation marks outside maths, no en- or em-dashes, no American spellings, £ for the one sum of money.
- Shape: per position the difficulty, pace and widget kind match version 1 (difficulty rises 2 to 5 in each paper). Paces sum to 1,500 s, 1,800 s and 600 s, the papers' minutes.
- Closure (`node tools/closure.mjs --target mock-oa-trader`): 22 courses. Every item is solvable from them. The extinction item (v2 B15) uses the first-step equation and smaller root that `puzzles/homework-2` item `hw2-ever-up` teaches on a different setup.

## Judgement calls the author flagged

A. Related sequence families in one version. My test is the brief's: does one worked solution, with numbers swapped, solve the other?
- v3 A3 (digits 1 and 2 only) and A10 (digit sum 5): the same shape, "spot the digit property, step to the next number with it". They sit beside v3 A8 (non-squares) and A11 (primes ending in 3), and v2 A3, A8 and A13, as filters. The property to spot differs each time, so I accept them, but v3 has four filter items of 15. Note only.
- v3 A4 (gaps are squares) and A5 (gaps are primes): "write the gaps, name them, add the next". This is the same method as version 1 A5, a step further. Siblings, not shared templates, because naming the gap sequence is the task. Note only.
- v2 A5 ($2^n + n$) and A9 ($n \cdot 2^n$): one subtracts and one divides, so the worked solutions differ. Accept. v2 A5 against version 1 is finding 4.
- v2 A10 (reversed squares) and A14 (add the reverse): different methods. Accept.
- v2 A13 and A15 both factorise into two primes, but A15's "next neighbouring pair" step fails on A13 (10 is not $2 \times 3$). Accept.
- v2 A11 (product of the two before) against version 1 A7 (Fibonacci): its own explanation solves it by Fibonacci on the exponents. A different operation, as the author says. Accept, as a note.

B. One trap family per version's rankings. Version 1 mixes five families across its six rankings. Version 2 uses one method six times (finding 5). Version 3 uses run counts in all six, plus "a random factor of $n$" events in c01, c03 and c05 and B1 (findings 6 to 8). The brief keeps topic weights, not method variety. Still, a ranking paper where one sum answers every item tests recall of that sum. My verdict: acceptable only after findings 5 to 8, and the orchestrator should record the choice in DECISIONS. Each version then still asks for one trap family, but no longer repeats a worked solution within the paper.
