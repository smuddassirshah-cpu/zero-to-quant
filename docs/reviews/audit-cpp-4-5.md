# Concept audit: cpp levels 4 and 5 (l14 to l23, review-4, review-5, homework-4, homework-5), round 1

Blind read at commit 6c01af87: no earlier review, audit or author report on this course was opened until the ledger and the findings below were written. Ledger: `docs/reports/audit-cpp-4-5-ledger.md` (342 rows: correct 306, wrong 7, imprecise 20, misleading 9, unverified 0; several rows can belong to one finding). Script: `docs/reports/cpp-L4-5-concepts.py`.

How each claim was checked. Every C++ claim and every code widget ran under the page's own compiler, not native clang: YoWASP clang 21.1.4 for wasm32 from the local CDN, in node, with `FLAGS`, `LINK`, the exception runtime and the WASI shim read out of `app/js/screens/cpp-worker.js` (`-std=c++17 -O1`, libc++ hardening in extensive mode, a throw ends the program with status 134) and each translation unit built by the widget's own `unit()` from `app/js/engine/widgets/cpp-grade.js`, so a submission gets the key the page would give (null, `compile`, `test-N`). The script runs 55 programs and compile probes and 186 graded submissions: the solution and starter of all 30 code widgets pass and fail as they should (60), every `feedback.byKey.test-N` line was swept with two or three natural codings of the slip it names (102 codings), and the level 5 widgets, which have no `test-N` lines, were given 22 wrong variants of their solutions and 2 correct ones (24). Sizes on other platforms were checked with the same compiler's front end (`--target=x86_64-unknown-linux-gnu` and `--target=x86_64-pc-windows-msvc`, `static_assert` on `sizeof`). The Catch2 claim was checked against the Catch2 source (`Approx::equalityComparisonImpl`, v2.13.10, the same rule in v3); Catch2 itself was not run. No line is timing-dependent: no test in these two levels measures time, and the longest hidden test ran 12 ms.

Sources: N4659 (the C++17 working draft; the page compiles C++17), cited by section; Meyers, *Effective Modern C++* (Items 14, 19, 23, 25, 29, 41); Stroustrup, *A Tour of C++* (§5.2, §11.2, §12); the Itanium C++ ABI §2.5; Cormen et al. ## What held

Iterator invalidation is stated per the standard (l14 screens[8], review-4, homework-5 `push`), and the one graded outcome of an invalid iterator is asked "in this app's run".
