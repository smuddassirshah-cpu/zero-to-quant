# Topic 1.9 (C++): second-reader findings

Scope: every lesson, review and homework file in `cpp` (18 lessons, 4 reviews, 4 homeworks) and `cpp-pricing` (12 lessons, 3 reviews, 3 homeworks), with both `course.json` files. There is no topic exam yet; the last section proposes one.
Method: every stated number recomputed (Python for maths, CRR trees and Black-Scholes; the app's own clang 21 / libc++ WebAssembly build for every C++ figure, through the Node replica of `app/js/screens/cpp-worker.js` and `app/js/engine/widgets/cpp-grade.js`). Every C++ `code` widget's solution was compiled and run against its hidden tests, and every starter checked to fail (`check.mjs`). A mutation pass planted simple wrong versions of every solution (operator swaps, dropped guards) and listed the ones that still pass every test (`mutate.mjs`). g++ 13.3, clang 18, AddressSanitizer and LeakSanitizer transcripts were rebuilt on Linux and compared with the consoles. Distractor values were re-derived from their `why`; tolerance overlaps scanned (`tolcheck.py`); style scanned (`style2.py`, `sentcount.py`). Scripts and logs are in the scratchpad folder `review-1.9`.
Format: `path | screen/item | severity | what is wrong | fix`. Severity: error = wrong number, false claim or wrong grading; warning = weak explanation, teaching or test gap; note = style or transcript detail.

## Proposed topic 1.9 exam (`app/content/exams/topic-1.9.json`)

25 items, 90 minutes, pass 0.7, at the 8.4 ramp: 5 at difficulty 2, 12 at 3, 5 at 4, 3 at 5. The `skills` map lists all ten skills: `cp-basics`, `cp-references`, `cp-memory`, `cp-classes`, `cp-stl`, `cp-build` (cpp) and `cx-numeric`, `cx-pricers`, `cx-perf`, `cx-testing` (cpp-pricing). Every item uses fresh numbers, not a lesson's. Code items run in the app: no `try`/`catch`, a fixed `-O1`, asserts on, and `raises` only for throws, asserts and exit codes, never for UB.

Must cover, with one item each unless stated:

1. cp-basics (d2): `int` against `double` division with a negative operand, such as `-11 / 4` and `-11 / 4.0`.
2. cp-basics (d3): signed overflow (UB) against unsigned wrap (defined), as a choice that names which is which.
3. cp-basics (d3, code): a loop over `std::cin` with a guard for an empty or one-value input.
4. cp-references (d2): a call by value against by reference, predicting the caller's value.
5. cp-references (d3): which calls compile against `T&`, `const T&` and `T` parameters, temporaries and `const` objects included.
6. cp-memory (d3): lifetime: a reference into a vector after `push_back`, or a returned pointer to a local; is it defined?
7. cp-memory (d4, code): convert a raw-`new` function with two early returns to `std::unique_ptr`, with a hidden live-object counter.
8. cp-memory (d3): `shared_ptr` use counts through copies, moves and a scope.
9. cp-classes (d3, code): a class with an invariant checked in the constructor and in every mutator.
10. cp-classes (d4): which special members the compiler still writes once one is declared (the l11 screens[7] pitfall: defaulted copy and move constructors delete assignment).
11. cp-classes (d3): a template deduction conflict, or counting instantiations.
12. cp-classes (d2): member against free `operator*`, which order compiles.
13. cp-stl (d4): iterator invalidation: erase in a loop, or a reference after reallocation.
14. cp-stl (d3): `map` against `unordered_map` for a stated job, with the complexity.
15. cp-stl (d4, code): sort with a two-key strict comparator and a lambda capture, plus `accumulate` with the right start type.
16. cp-build (d2): compiler error against linker error from a transcript.
17. cp-build (d3): a CMake fix (`target_link_libraries`, PUBLIC against PRIVATE) and which build type defines `NDEBUG`.
18. cx-numeric (d4): a cancellation rewrite (for example $\sqrt{x+1} - \sqrt{x}$) or a tolerance that is `==` in disguise at a stated magnitude.
19. cx-numeric (d2): seeded `std::mt19937` reproducibility and why libc++ and libstdc++ differ.
20. cx-pricers (d5, code): a binomial pricer on one vector for a new payoff through `const Payoff&`, with the growth convention stated.
21. cx-pricers (d3): a new Black-Scholes value with parity, at T ≠ 1 so that the `σ√T` slip shows.
22. cx-perf (d3): batch size for a clock tick, the median, and the dead-code trap.
23. cx-perf (d3): cache lines for a strided walk or an array of structs.
24. cx-testing (d5, code): write tests that pass a supplied pricer and fail three planted bugs (the cpp-pricing l12 kit).
25. cx-testing and cx-perf (d5, longform, rubric summing to 10): the exit task in small, a short note on porting and timing a pricer against Python. It names the method, the flags, the agreement tolerance and the caveats. Ideally the learner's own Python timing feeds it, once the exit gap above is closed.

Items 20, 24 and 25 are the three difficulty-5 items, so the exam tests the exit skill rather than recall.
