Branch `ai-w7-llm-apps`. Brief: `docs/briefs/llm-apps.md` Level 3. There is no language model in the browser: every agent screen runs against a **scripted model** in `llm_apps_ops_l3.py` that returns fixed replies by task id and turn, and the prose says so where real systems differ (sampling, steering by descriptions, API pairing of tool results). Prompting is not taught (that is `ai-use`); the level teaches the code around a model.

## The scripted model and its tasks

`respond(messages, tools)` reads the task id from the first user message ("[T07] ...") and the number of assistant turns; for self-correcting scripts it also reads the last tool error. 20 planted tasks (`TASKS`): direct closes (T01, T02, T16), moves needing two closes and `pct_change` (T03, T04, T17), searches (T05, T19), broken JSON (T06, T18), an unknown tool name (T07), an integer date (T08, T15), a missing date (T09), endless searches (T10, T20), a confident wrong answer with no tool (T11), a holiday close where the tool raises (T12), two valid paths (T13) and a right answer from memory with no tool (T14). A script fixes its call only when the error names what was wrong (JSON; the real tool names; the field and 'string'; the missing field; 'no close'). `DEMO_TASKS` holds D01, which picks a tool by its description (l9's hook).

Behaviours claimed, each from running the stub (checked in the script by a separate harness): clear errors fix 7 of 7 planted errors and 16 of 20 tasks succeed; 'invalid input' fixes 0 and 9 succeed; success rates 0.80 (standard error 0.0894) and 0.45 (0.1112), paired difference 0.35 (standard error 0.1094, 3.2 standard errors); answer-only grading gives 0.85 because T14 counts; the fixed workflow answers 20 of 20.

## Numbers and their sources

Route B in the script is a separately written validator, call reader, loop and scorer; every console trace on screen is regenerated by it and compared line by line, and its numbers (closes, note ids, dates) are covered by that comparison. Compound reliability by repeated multiplication and by $e^{n\ln p}$: $0.95^5 = 0.7738$, $0.95^{10} = 0.5987$, $0.95^{20} = 0.3585$, $0.99^{20} = 0.8179$ (the planner's figures, confirmed); 0.70 on 40 tasks has standard error 0.0725. Other figures: T03 needs 4 model calls (8 messages); T10 makes 6 calls under a cap of 6 and 3 with the repeat check; T12 answers 95.98; review 0.8571, 0.0635, 0.5314; homework $0.97^{12} = 0.6938$, paired $2/30 = 0.0667$; problem set $0.96^8 = 0.7214$, 11.14 failures expected in 40, standard error 0.0709.

## Shared module `llm_apps_ops_l3.py` (v1.0; frozen once merged; imports `llm_apps_ops_l1`)

- `respond(messages, tools) -> {"type": "tool_call", "name", "arguments"} | {"type": "answer", "text"}`
- `get_close(ticker, date) -> float` (raises ValueError for an unknown ticker or a date with no close); `search_notes(query, k=3) -> [note ids]` (L1 TF-IDF over the 180 notes); `pct_change(a, b) -> float` (rounded to 2 places)
- `SCHEMAS`, `DESCRIPTIONS`, `TOOLS` (`{name: {"fn", "schema", "description"}}`), `TASKS`, `DEMO_TASKS`, `PRICES`, `TICKERS`, `DAYS`, `task_message(task)`
- Private but used by the homework's hidden setup: `_task(tid, kind, question, args)` and `_BY_ID` (hidden tasks H01 to H08 are registered there).

Data and provenance: no data file added; the four tickers (CORR, DUNM, ELRY, HALL), their March 2024 closes (seeded random walk, `random.Random(7)`) and every task are **invented**.
